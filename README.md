# Lava.top + PuzzleBot — Ян Бейкер

Оплата встречи через Lava.top из PuzzleBot с записью в Google Таблицу «Ян Бейкер регистрации».

## Как это работает

1. В боте человек оставляет почту и нажимает кнопку тарифа.
2. Кнопка открывает страницу оплаты (`docs/index.html`, GitHub Pages) — там выбор валюты и промокод.
3. Страница просит скрипт (`lava-baker.gs`, Apps Script в таблице) создать счёт в Lava на почту человека и переводит на оплату.
4. После оплаты Lava возвращает на страницу «Оплата прошла успешно».
5. Скрипт пишет оплату на лист «Lava.top» (с тарифом: 1750 / 2750 / 3750), запускает в боте команду
   выдачи доступа `ACCESS_COMMAND` и на листе «PuzzleBot» ставит в столбце «Оплата» «Успешно» / «Нет оплаты».
   Раз в 5 минут скрипт сам перепроверяет неоплаченные счета.
6. Лист «Итоги» считается формулами таблицы, скрипт его не трогает: сколько оплатили и сколько
   зарегистрировалось на листе «PuzzleBot», а также оплаты, выручка, комиссия Lava (ставка в ячейке B10)
   и сумма к получению по каждому тарифу — по столбцу «Тариф» листа «Lava.top».

## Настройка

1. Таблица → Расширения → Apps Script → вставить `lava-baker.gs`.
2. Вверху скрипта вписать `LAVA_API_KEY`, `SECRET`, `PUZZLEBOT_TOKEN` и название команды бота `ACCESS_COMMAND`.
   Ключ, токен, секрет и название команды вписываются только в Apps Script — в GitHub их не храним.
   ID цен трёх тарифов уже вписаны в `TARIFFS`.
3. Выпустить новую версию развёртывания (адрес `/exec` не меняется).
4. Меню «Lava» → «1. Включить автопроверку» (нажать ещё раз после обновления скрипта).
5. Вебхук Lava (чтобы оплаты приходили сразу): в Lava → Интеграции → Webhooks добавить адрес
   `…/exec?key=SECRET` (SECRET — строка из скрипта), события «Успешная оплата» и «Возврат».
   Проверка: после оплаты на листе «Лог» появляется строка `POST` со статусом `saved`.

## Защита и надёжность

- Повторная оплата: если человек уже оплатил (по почте или Telegram ID), второй счёт не создаётся —
  страница пишет, что доступ уже отправлен.
- Счёт, закрытый после отказа банка, повторно не выдаётся — создаётся новый.
- Если Lava временно сбоит, создание счёта повторяется до 3 раз; человеку показывается понятный текст.
- Telegram ID сохраняется при повторной оплате после неудачи; если его нет у оплаченного счёта —
  берётся из других счетов этого человека, чтобы доступ всё равно ушёл в бот.

## Нагрузка

- Счета в Lava создаются без очереди: скрипт блокирует таблицу только на запись строки.
- Неоплаченные счета младше часа проверяются каждые 5 минут, старше — раз в 3 часа,
  пачками по 20 запросов одновременно. Через 3 дня неоплаченный счёт помечается истёкшим.
- Цены тарифов обновляются из Lava раз в 30 минут и хранятся в кэше — страница оплаты открывается быстро,
  кнопки валют видны сразу.
- С вебхуком оплаты приходят сразу, а проверки по расписанию остаются страховкой.
- Вебхук принимает только оплаты счетов из бота и продукта «Ян Бейкер», остальные продукты аккаунта пропускает.
